Running RUXP

How to build it, verify it without a test target, change a rule without a build, close a season, and ship. Written for whoever picks this up next, human or agent.

Build and run

open RUXP.xcodeproj
# or from the command line
xcodebuild -scheme RUXP -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build
xcodebuild -scheme "RUXP Watch App" -destination 'generic/platform=watchOS Simulator' build

Xcode 16 synchronized folders: a new Swift file under Shared/, RUXP/, or RUXP Watch App/ needs no project edit. Shared/ compiles into both targets, so it stays Foundation-only. Build without CODE_SIGNING_ALLOWED=NO when HealthKit matters. There is no test target; verification is build, launch arguments, screenshots, and reading the JSON files.

Debug launch arguments

All wrapped in #if DEBUG and mirrored in Settings › Developer.

ArgumentEffect
-RUXPSkipMinimumno 10-minute minimum for completion XP
-RUXPSkipHealthKitbypass HealthKit (simulators)
-RUXPSkipGameCenterno sign-in, scores, or live counts
-RUXPLoadSamplesseed 7 sample workouts on an empty install (dated relative to today)
-RUXPEventClock friday|sunday|tuesdayfreeze the event clock at that day
-RUXPTab train|profileopen on that tab
-RUXPLiveScene lobby|active|completeopen the Live lobby, a joined workout, or the reward screen
-RUXPScreen seasonpass|settings|livehistory|archivedpassopen that sheet at launch
-RUXPSeason S00|S01pretend that season is current: rollover, recap, ladders, boards
-RUXPLastSeen 3d|18h|45mpretend the last visit was that long ago
-RUXPWorldDemowith Game Center off, seed friends and rank so every ledger line renders
-RUXPLiveOps off|<path.json>no rules, or a local calendar instead of the remote one
UDID=$(xcrun simctl list devices booted | grep -o '[0-9A-F-]\{36\}' | head -1)
ARGS=(-RUXPSkipGameCenter -RUXPSkipHealthKit -RUXPLoadSamples -RUXPSkipMinimum -RUXPLiveScene complete)
xcrun simctl launch $UDID com.whussey.ruxp "${ARGS[@]}"
xcrun simctl io $UDID screenshot reward.png

In zsh, build arguments as an array or simctl launch receives one argument. Find the app's files with xcrun simctl get_app_container $UDID com.whussey.ruxp data; read its log with xcrun simctl spawn $UDID log show --last 3m --predicate 'subsystem == "com.whussey.ruxp"'.

Verification recipes

  1. Decode compatibility. Copy an older player_progress.json into the container, launch, confirm level and XP survive and the log has no "Failed to load progression".
  2. Season rollover. Launch with samples in S00, equip a title and badge, relaunch with -RUXPSeason S01: the recap appears once; Profile keeps the S00 cosmetics and lists S00 in SEASONS; the archived ladder still equips.
  3. Live Ops. Write a local calendar whose window covers today, launch with -RUXPLiveOps path -RUXPSkipMinimum -RUXPLiveScene complete: rule rows on the reward screen, the tag on Home. A file with a 5× factor or a 40-day window must be rejected in the log.
  4. Return ledger. -RUXPLastSeen 3h shows nothing; 3d shows the rituals and the new week; 3d -RUXPWorldDemo shows every line, capped at four; -RUXPSeason S01 with an S00 baseline shows the recap and no ledger.
  5. On a device. Sign into Game Center; two accounts that are friends for the friend and rank lines; two devices for the Training Room.

Change a rule without a build

  1. Edit docs/live.json. Dates are local wall-clock yyyy-MM-dd'T'HH:mm.
  2. Bump version. It must be at least the bundled version.
  3. Stay within the caps: 32 rules, 14-day windows, factor 1–3, bonus 0–1000, unique ids, known types. A file outside them is rejected wholesale.
  4. Push. GitHub Pages serves it; each app fetches at most once an hour on foreground. Settings › Developer shows the source and version.
  5. Mirror durable rules into LiveOpsCatalog.bundled at the next build so offline players see them too.
{ "id": "s00-pr-weekend", "title": "PR WEEKEND", "eyebrow": "THIS WEEKEND ONLY",
  "description": "Every PR pays double. Bring the voice notes.",
  "start": "2026-09-26T00:00", "end": "2026-09-28T00:00",
  "rule": { "type": "multiplier", "reason": "personalRecord", "factor": 2 } }
// other rules: {"type":"flatBonus","amount":250}  {"type":"startedBefore","hour":8,"amount":250}

Close a season, open the next

  1. Before it starts: the season exists in SeasonCatalog, its ladder in SeasonPassCatalog, and season_xp_sNN + season_goal_sNN exist in App Store Connect (Scripts/gamecenter_setup.py --all-seasons). S01 is done on all three.
  2. Ship the build that knows the new season before its start date. The rollover is client-side; a player who launches after the date gets the recap on that launch.
  3. Schedule the finale rule in Live Ops for the last weekend.
  4. After the date, nothing to do. Season XP restarts, records are frozen, cosmetics persist. Test any of it early with -RUXPSeason.

Ship

cp Config/Secrets.example.xcconfig Config/Secrets.xcconfig   # paste the OpenAI key; gitignored
git config core.hooksPath .githooks                           # refuses commits containing an sk- key
# bump CURRENT_PROJECT_VERSION in RUXP.xcodeproj/project.pbxproj (4 places)
df -h /System/Volumes/Data                                    # archives need ~20 GB free
Scripts/ship.sh                                               # archive → export → TestFlight upload

Xcode must be signed into the Apple ID (Settings › Accounts); the App Store Connect API key in this setup can manage Game Center but not cloud signing. Internal TestFlight only until the privacy policy URL is on the App Store record. Achievement images (512×512) are still needed before App Store release.
