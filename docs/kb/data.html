Data and Game Center

No accounts of our own, no analytics, no tracking. Everything is on the phone as JSON, and the only things that leave it are voice notes to OpenAI for parsing and, with Game Center on, XP totals, a week streak, milestones, and an "I'm training" ping.

The compatibility rule

Season 00 is live and testers have player_progress.json files on their phones. Every field added to a persisted struct is Optional with a nil default, or every existing profile fails to decode and blanks. ProgressionService.save() stamps schemaVersion on every write; a file without one is from builds 1–4, which is how a legacy "S01" file (builds 1–3 called the launch window S01) is told apart from a real Season 01 file.

Verified for build 5: a build-4-shaped file decodes with XP intact; a legacy S01 file is renamed to S00 with cosmetics remapped and no record created; a corrupt world snapshot or live ops cache is treated as a first launch.

Game Center

Sign-in is silent if the player is already in Game Center. Scores are absolute totals, never deltas, one board per call so an unconfigured board cannot block the others. Achievements are reported only when the percent grows. A first sign-in gives a card still named PLAYER the Game Center alias.

The five presence boards (active_a, active_b, trained_today, event_friday_night, event_sunday_reset) are recurring, configured in App Store Connect in US Eastern with padding so every US time zone's local ritual falls inside. All boards and achievements for S00 and S01 exist in App Store Connect; Scripts/gamecenter_setup.py creates them idempotently.

Privacy

Voice notes are sent to OpenAI for transcription and parsing. During Season 0 the app ships a developer-provided key; you can replace it with your own in Settings. Game Center is optional and can be turned off. The Live Ops fetch is a plain GET of a public JSON file with no identifiers. The privacy policy says the same in fewer words.
